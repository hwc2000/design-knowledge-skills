# 설계 결정 기록

## 왜 스킬인가

- 스킬은 설명 한 줄만 항상 읽히고, 본문은 그 일을 할 때만, 세부 자료(`references/`)는 필요한 부분만 열린다.
- 그래서 자료가 많아도 한 번에 다 읽히지 않는다. 중요한 건 분량이 아니라 "필요한 조각을 바로 찾게 나눴는가"다.

## 원칙: 강의 순서가 아니라 설계 질문으로 묶는다

설계할 때 떠오르는 건 "3주차 강의"가 아니라 "이 두 서비스는 어떻게 통신하지?" 같은 질문이다. 그래서 스킬 하나 = 설계 질문 하나로 둔다.

질문 목록은 처음에 일반적인 분류로 초안을 잡고, 실제 강의 주제 목록에 태그를 붙여 본 뒤 너무 큰 묶음은 나누고 작은 건 합쳐서 정했다. 지금 9개는 첫 과목(분산처리)에서 나온 것이고 **닫힌 목록이 아니다.** 다른 과목이 기존 질문에 맞지 않는 내용을 가져오면(예: 배포·운영, 관측, 보안) 새 설계 질문 스킬을 만든다.

### 왜 과목을 위에 두지 않나

`분산처리/` 아래에 질문들을 넣는 구조도 검토했지만 채택하지 않았다.
- 설계할 때 떠오르는 건 과목이 아니라 질문이다. 과목을 위에 두면 "이 질문은 어느 과목에 있었지?" 를 다시 골라야 한다.
- 같은 질문(예: 복제)에 대한 이론 과목과 인프라 과목의 내용이 한 스킬 안에 나란히 있어야 비교·보완이 된다.
- 과목을 위에 두면 과목 하나가 큰 스킬 하나가 되거나(질문별로 골라 열리는 장점이 사라짐), `분산처리-복제` · `인프라-복제` 처럼 같은 질문이 과목 수만큼 따로 생긴다(설명 한 줄이 비슷해 어느 쪽을 열지 헷갈림).

과목은 각 스킬의 `references/<과목>/` 폴더로 들어간다. 과목이 위가 아니라 아래에 있을 뿐, 과목별로 나뉘어 있는 것은 같다.

## 스킬 하나의 모양

```
skills/design-failure/
├── SKILL.md                 ← 직접 씀: 먼저 물을 질문 · 선택지 표 · 흔한 함정 · 쓰는 규칙 + 자동 목록
└── references/
    ├── <과목A>/NN강-….md    ← 스크립트가 지식트리에서 뽑아 넣음 (그 강의 중 이 스킬 주제만)
    ├── <과목B>/…            ← 다음 과목은 폴더만 추가
    └── 관련-주제.md          ← 다른 스킬에 있는 걸치는 주제 링크 (자동)
```

- **SKILL.md 에는 "결정"만.** 상황 → 선택지 → 장단점. 개념 설명은 references 로 보낸다.
- **SKILL.md 는 과목·강의·제품에 묶지 않는다.** 어느 과목을 넣어도 통하는 판단 기준으로 쓴다. 제품 이름은 "예:"로만, 강의 번호는 쓰지 않는다.
- **references 는 근거이지 정답이 아니다.** 실무와 맞지 않으면 그렇다고 말하게 규칙에 적었다. 강의에 없는 지식을 덧붙이면 "(강의 밖)" 으로 표시한다.
- **출처를 남긴다.** references 파일마다 원래 지식트리 링크가 있어 깊게 볼 때 돌아갈 수 있다.

## 태그

### 주 태그 (본문 위치)

- 단원마다 기본 태그를 주고(`tag.py` 의 `U`), 주제 이름에 특정 낱말이 있으면 덮어쓴다(`OV`).
- 덮어쓰기는 모든 강의에 똑같이 걸린다. 그래서 새 규칙은 **짧은 낱말로 쓰지 않는다.** 예: 새 강의의 "CockroachDB 팔로워 읽기"를 일관성으로 보내려고 `CockroachDB` 만 쓰면, 예전 강의의 "CockroachDB(시계·순서)" 주제까지 옮겨 간다. 규칙을 넣기 전에 같은 낱말을 쓰는 기존 주제를 검색한다.
- `배경`(복습·다음 강의 예고 등)은 어느 스킬에도 넣지 않는다.

### 보조 태그 (링크)

- 작품에 태그를 여러 개 붙여도 작품이 복사되지 않는 것처럼, 본문은 한 곳에 두고 다른 스킬에는 한 줄 링크만 둔다.
- 규칙은 `tag.py` 의 `SEE`(주제 이름 낱말 → 태그 목록). 주 태그와 같은 스킬은 빼고 주제당 최대 2개. 너무 많이 달면 모든 스킬에 모든 링크가 쌓여 나눈 의미가 흐려진다.
- 링크는 낱말 규칙이라 빠지는 주제가 있을 수 있다. 그래서 SKILL.md 규칙에 "링크에 없어도 걸치면 다른 design-* references 를 직접 Grep 한다"를 넣었다. 링크는 지름길이지 전부가 아니다.

### 과목끼리 겹칠 때

1. 같은 개념이 다른 과목에 있으면 같은 스킬의 다른 과목 폴더에 둔다. 합치지 않는다.
2. 관점이 다르면 둘 다 본다 (예: "왜·무엇을 보장하나" 는 이론 과목, "어떻게 구성·운영하나" 는 인프라 과목).
3. 내용이 다르면 출처와 함께 둘 다 보여 주고 어떤 조건에서 무엇이 맞는지 말한다. 몰래 하나를 고르지 않는다.
4. 합치지 않는 이유: 출처를 추적할 수 있고, 한 과목을 다시 빌드해도 다른 과목 자료가 덮이지 않는다.

## 새 강의·새 과목 추가

과목마다 설정 파일 하나: `pipeline/subjects/<과목>.json`

```json
{"subject": "분산처리",
 "lectures": [{"lec": 20, "id": "<아티팩트 id>", "tags": ["배경", "복제", "복제", "장애", "일관성", "복제", "복제"]}]}
```

- `lectures` 순서가 정렬 순서다. **강의 번호 `lec` 은 선택**이다. 있으면 파일 이름 앞에 `NN강-` 을 붙이고, 없으면 제목만 쓴다. 과목이 폴더로 나뉘어 있어 번호가 겹쳐도 충돌하지 않는다.
- `tags` 는 단원 순서대로 주 태그. 단원 수와 다르면 extract 가 멈춘다.

1. 지식트리 페이지를 HTML 로 준비한다. JS 로 트리를 그리는 예전 페이지는 headless 크롬으로 렌더링한 DOM 을 쓰고, 키트로 만든 페이지는 빌드한 HTML 을 그대로 쓴다. 파일 이름은 `<아티팩트 id>.html`.
2. 과목 설정의 `lectures` 에 새 강의를 넣고 뽑는다. 끝에 아티팩트 id 를 주면 그 강의만 뽑는다.
   `python3 -I pipeline/extract.py pipeline/subjects/분산처리.json <HTML폴더> out.json <id>`
3. 필요하면 `tag.py` 의 `OV`·`SEE` 에 규칙을 넣는다 (위 주의 참고). 처음 보는 설계 질문이면 새 스킬(SKILL.md 포함)을 만들고 `build_skills.py` 의 `SKILL_OF` 에 추가한다.
4. `python3 -I pipeline/build_skills.py out.json <과목이름>` — 입력에 든 강의 파일(출처 아티팩트 id 로 찾음)만 다시 쓰고, 링크와 목록을 전부 새로 만든다. 규칙만 고쳤으면 `--links-only`.
5. 빌드 전 스킬 폴더를 백업해 두고, 끝나면 diff 로 기존 강의 파일이 그대로인지 확인한다.
6. 새 스킬 폴더는 SKILL.md 를 넣은 채로 한 번에 만든다. 빈 폴더를 먼저 만들면 Claude Code 가 바로 인식하지 못할 수 있다.
